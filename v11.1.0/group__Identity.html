Identity

Detailed Description

Work with the cross-game identity behind a player's sessions.

An identity is the human behind one or more player accounts in a publisher, shared across every game that publisher owns. Use the identity methods to read the identity a session is linked to, look identities up, record a provider credential against an identity, and preview or execute a merge of two identities that turn out to belong to the same person.

Merging is destructive and never happens automatically: LootLocker returns the games in which both identities have a live player and the calling code must choose which player to keep in each.

◆ ELootLockerIdentityProvider

enum class ELootLockerIdentityProvider : uint8
strong

Platforms that can be presented as a credential when linking a provider to an identity.

The enumerator names are the wire values the backend accepts, so they are sent as-is. These are the platform catalog slugs used by LootLocker, which are not the same catalogue as ELootLockerAccountProvider.

Always send the canonical enumerator when linking. The backend accepts the aliases "ios", "android" and "luna" and stores whichever form was sent, but a stored alias resolves to Unknown because this SDK only maps canonical slugs.

Zero on purpose: an unpopulated or unparseable value must not land on a real provider.

Get the identity the current session is linked to, including the publisher it belongs to, the provider credentials linked to it and, when populated, the games it has been active in.

The Providers list carries the credential ids that UnlinkProvider takes; the provider's own user identifier is deliberately not returned. Each entry's Provider_type is resolved from its Provider slug, and is Unknown for a slug this SDK does not map.

The session must be linked to an identity; a session that is not is answered with 403.

◆ LinkProvider()

FString ULootLockerSDKManager::LinkProvider ( const FLootLockerIdentityLinkRequest & Request,
const FLootLockerIdentityLinkResponseDelegate & OnCompletedRequest,
const FString & ForPlayerWithUlid = "" )
static

Record a provider credential against the identity of the current session, so a later session presenting the same credential resolves to this identity instead of minting a second one.

Linking is idempotent: a credential this identity already owns answers created = false. When another identity in the publisher owns the credential the call answers 409 and links nothing; the merge offer is surfaced on the response's Conflict field and can be resolved with MergeIdentities. LootLocker never links a credential across identities on the player's behalf.

The backend stores the provider slug exactly as it is sent, so always send the canonical enumerator; sending an alias would make the stored slug differ from what GetIdentity reports for other credentials of the same provider. Unknown is rejected before the request is sent.

◆ MergeIdentities()

FString ULootLockerSDKManager::MergeIdentities ( const FLootLockerIdentityMergeRequest & Request,
const FLootLockerIdentityMergeResponseDelegate & OnCompletedRequest,
const FString & ForPlayerWithUlid = "" )
static

Merge another identity into the current one, keeping the current identity.

The merged identity is tombstoned, its credentials and player links move to the kept identity, and its sessions are revoked. Every game in which both identities have a live player must carry a resolution naming the player to keep; the other player of that game is soft-deleted. A missing or invalid resolution answers 400 and writes nothing.

This is destructive and never runs automatically. Get the conflicts from PreviewIdentityMerge (or from the conflict of LinkProvider) and let the player choose.

◆ UnlinkProvider()

FString ULootLockerSDKManager::UnlinkProvider ( const FString & CredentialId,
const FLootLockerDefaultDelegate & OnCompletedRequest,
const FString & ForPlayerWithUlid = "" )
static

Remove a provider credential from the current identity.

Get the credential id from the Providers list of GetIdentity. The provider's own user identifier is never returned, so the id is the only reference available to a game client.

The last remaining credential cannot be removed, because the identity would become unreachable; that case is answered with 422.
